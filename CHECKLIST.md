# ENDZONE requirement coverage checklist (spec sections 1–24)

Status key:
- **Implemented**: built, and checked by a test or by a live run.
- **Fallback-only**: built, but the live source does not currently supply the input, so a labeled fallback is used.
- **Blocked**: cannot be done in this environment.

Test numbers refer to `tests/acceptance.test.js` (T1–T18), `tests/e2e-ui.test.js` (UI), `tests/loading-timers.test.js` (TIMERS), `tests/spot-factors.test.js` (SPOTF), `tests/standalone.test.js` (SA), and `tests/smoke-live.mjs` (SMOKE). ## Changes in the second pass
- §3: the 20s/50s loading timers are now tested (TIMERS). It uses a hanging /api/data and a fake clock in headless Chrome. It checks there is no retry before 20s, Try again after 20s, a plain timeout at 50s, that the abandoned request is aborted on the server side, and that retry issues a new request.
- §8: distance to gain now enters the bounded play-quality factor. Shorter-than-league distance at the same spot nudges the rate up, longer nudges it down, at most ±2%, weighted by looks/(looks+10). Previously it was collected only.
- §10: yard-line-specific defense allowances now enter predictions per spot (`defenseSpotFactor`). It compares the defense's TD rate in that spot with league, shrinks with k=60 looks, and is bounded 0.94–1.06. A lift is withheld without real recent red-zone looks, and it is shown in the Advanced evidence table. Previously it was displayed only. Overlap with the position-softness factor is partial; the tight bound is the guard against double counting. SPOTF covers both.
- Deployment: tunnels were attempted and failed (see the last row). A standalone single-file build was added (SA).
